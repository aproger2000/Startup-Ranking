# Топ стартапов России — веб-сервис

Клиент-серверный сервис с рейтингом молодых российских стартапов: база
данных на SQLite, JSON API, публичный мобильный/десктопный фронтенд и
админ-панель для пополнения базы. Написан на чистом стандартном Python
(без FastAPI/Django/pip-зависимостей) — разворачивается без шага сборки.

## Структура проекта

```
backend/
  app/
    server.py       — HTTP-сервер (http.server), роутинг /api/* и статики
    db.py            — доступ к SQLite (создание таблиц, CRUD, upsert)
    scoring.py       — формула расчёта скора
  frontend/
    index.html       — публичный рейтинг (мобильная и десктопная вёрстка)
    admin.html        — админ-панель (добавление/редактирование/массовая загрузка)
  data/
    seed.json        — исходный набор из 137 компаний (133 РФ + 4 диаспора)
  tools/
    push_updates_example.py — шаблон скрипта для автопополнения через API
  boot.py            — точка входа: при пустой базе подгружает seed.json, затем стартует сервер
  generate_seed.py   — как был получен seed.json (для справки, для деплоя не нужен)
  seed_db.py         — ручная загрузка seed.json в локальную базу (для разработки)
render.yaml          — конфигурация деплоя на Render (Blueprint)
```

Внешних зависимостей нет — используется только стандартная библиотека
Python 3 (`http.server`, `sqlite3`, `json`). `pip install` не требуется.

## Локальный запуск

```bash
cd backend
ADMIN_API_KEY=мой-секретный-ключ python3 boot.py
# сервис на http://localhost:8000  (публичный рейтинг)
#            http://localhost:8000/admin.html  (админ-панель)
```

При первом запуске `boot.py` увидит, что база пуста, и автоматически
загрузит `data/seed.json` (137 компаний). При последующих запусках
загрузка не повторяется — уже сохранённые данные (в том числе изменения
из админ-панели) не затираются.

Порт и путь к базе можно переопределить переменными окружения `PORT` и
`DB_PATH` (по умолчанию — `backend/data/startups.db`).

## Деплой на Render

В репозитории уже есть `render.yaml` (Render Blueprint) — самый быстрый способ:

1. Залейте этот проект в свой Git-репозиторий (GitHub/GitLab).
2. В панели Render: **New → Blueprint**, укажите репозиторий — Render
   прочитает `render.yaml` и сам создаст веб-сервис с нужными настройками
   (рабочая директория `backend`, команда запуска `python3 boot.py`,
   постоянный диск на 1 ГБ, смонтированный в `/var/data`).
3. После создания сервиса откройте **Environment** и задайте секретную
   переменную `ADMIN_API_KEY` (в `render.yaml` она намеренно оставлена
   пустой — `sync: false` — чтобы не хранить секрет в репозитории).
4. Сохраните — Render передеплоит сервис с новым ключом.

Если предпочитаете настроить сервис вручную (без Blueprint), в панели
Render создайте **Web Service** из репозитория со следующими параметрами:

- **Root Directory:** `backend`
- **Runtime:** Python 3
- **Build Command:** `true` (сборка не нужна — зависимостей нет)
- **Start Command:** `python3 boot.py`
- **Health Check Path:** `/api/health`
- **Environment Variables:** `ADMIN_API_KEY` (свой секрет), опционально `DB_PATH=/var/data/startups.db`
- **Disk:** добавьте постоянный диск (Persistent Disk), например 1 ГБ,
  смонтированный в `/var/data`, и укажите этот путь в `DB_PATH`

### Важно про постоянное хранилище

Файловая система у веб-сервисов Render **не сохраняется** между деплоями
и перезапусками, если не подключён Persistent Disk. Без диска база будет
пересоздаваться из `seed.json` при каждом деплое, и все изменения через
админ-панель будут теряться. Persistent Disk доступен на платных планах
Render (starter и выше) — так как у вас есть подписка, просто убедитесь,
что диск подключён и `DB_PATH` указывает на путь внутри него (в
`render.yaml` это уже настроено на `/var/data/startups.db`).

## API

Все ответы — JSON, `UTF-8`.

**Публичные, без авторизации:**

- `GET /api/health` — проверка живости
- `GET /api/companies?category=domestic&status=active&sector=...&search=...&sort_by=score&sort_dir=desc&limit=100&offset=0` — список компаний
- `GET /api/companies/{id}` — одна компания
- `GET /api/sectors?category=domestic&status=active` — список отраслей со счётчиками
- `GET /api/stats?category=domestic&status=active` — агрегированная статистика
- `GET /api/methodology` — текст методологии (источники, формула скора, ограничения)

`category`: `domestic` (российский рынок, по умолчанию) или `diaspora`
(стартапы с российскими основателями, работающие в основном за рубежом).
`status`: `active` (по умолчанию), `closed`, `distress`, либо пустая
строка — без фильтра по статусу.

**Админские, требуют заголовок `X-Api-Key: <ADMIN_API_KEY>`:**

- `POST /api/admin/companies` — создать компанию (обязательны `name`, `sector`; 409, если такая пара уже существует)
- `PUT /api/admin/companies/{id}` — обновить компанию
- `DELETE /api/admin/companies/{id}` — удалить компанию
- `POST /api/admin/companies/bulk` — массовый upsert (тело — JSON-массив объектов или `{"items": [...]}`); апсерт по паре (name, sector)

Скор пересчитывается сервером автоматически при любом создании/обновлении
— вручную его передавать не нужно (переданное значение будет проигнорировано).

## Пополнение базы данных

Есть два способа:

1. **Вручную, через админ-панель** (`/admin.html`) — форма добавления/
   редактирования одной компании и текстовое поле для массовой вставки
   JSON-массива. Ключ доступа вводится один раз и хранится в браузере.

2. **Программно, через `POST /api/admin/companies/bulk`** — для
   автоматического пополнения на основе публичных данных. Шаблон-пример
   лежит в `backend/tools/push_updates_example.py`: он показывает формат
   данных и то, как вызвать эндпоинт. На основе него можно:
   - настроить периодическую задачу, которая исследует открытые источники
     (пресс-релизы, отраслевые рейтинги, vc.ru, RB.RU и т.п.) и отправляет
     найденные обновления через этот эндпоинт;
   - подключить любой внешний планировщик (cron, Render Cron Job и т.п.),
     который будет запускать такой скрипт по расписанию.

   Если хотите, чтобы такое пополнение выполнял Claude по расписанию —
   после деплоя пришлите адрес сервиса и админ-ключ, и можно будет
   настроить регулярную задачу (например, раз в неделю), которая ищет
   свежие данные о стартапах и обновляет базу через этот же API.

## Формула скора

```
Скор = Выручка (0–38 баллов, лог-шкала)
     + Рост выручки (от −24 до +24, знак сохраняется)
     + Финансирование (0–20 баллов, лог-шкала)
     + Признание (IPO/pre-IPO +10, официальный отраслевой рейтинг +5, крупный инвестор +3)
     − 6, если ни выручка, ни рост, ни финансирование не раскрыты
```

Актуальный текст методологии, источников и ограничений всегда доступен
через `GET /api/methodology` и отображается внизу главной страницы.
